# 研究工作台 UI 与 spec 同步维护

## 职责

- `/research` 工作台四区布局：顶栏（场景/交易对/期限/行情时间与连接状态）、左栏（自选/会话/历史研究）、中栏（K 线与已确认结构/多周期结论/关键价位）、右栏（对话/建议卡/支持反对证据/来源抽屉）。
- 永续表单与结果卡、事件表单与结果卡（期限预测/盈亏平衡胜率/EV/倒计时/复盘状态）。
- 证据联动：点击证据 → K 线定位或打开原文页码。
- 异常状态全覆盖：数据过期/模型训练中/报价缺失/引用不足/取消/错误。
- **spec 同步**：保证 `docs/specs/ui.md` 与实际实现一致。

## 维护时必须遵守的纪律

- **改交互必须回写 spec 状态**：任何交互、布局、状态展示的实际变更，必须在同一改动中更新 `docs/specs/ui.md`；实现完成后将其状态行从 `planned` 升级为 `implemented`，验收通过后再升级为 `verified`。代码与 spec 不一致视为未完成。
- **历史回答不被图表操作污染**：切换周期/交易对不修改已发布 run 的结果快照；界面展示以 run 记录（snapshotId/asOf/各版本号）为准。
- **不可用态显式展示**：模型未就绪、期限未验证、数据过期、报价缺失时必须显示明确的不可用原因，不得静默隐藏或显示空概率。
- **1w 研究模式标识**：事件合约 1w 期限的结果卡必须有显著「研究模式」标识，不得与币安已有的 10m/30m/1h/1d 产品混淆。
- **provisional 视觉区分**：未确认结构在图上用虚线等方式与已确认结构区分；摆动点可画回 pivot 位置，但标注须体现确认时间 `knownAt`。
- **数值只展示代码计算结果**：盈亏、EV、盈亏平衡胜率、概率等数值来自后端契约字段，前端不自行估算；概率为空时显示空态而非编造数字。
- **沿用现有深色 token**：`--bg-0..3`、`--cyan`、`--up`、`--down` 等见 `web/src/styles.css`，不引入新色系。
- **移动端与可访问性**：<760px 切换为图表/对话/证据三标签；键盘可达、aria 标签齐全。
- **SSE 协议一致**：进度事件渲染严格按 `docs/specs/api-storage.md` 的 SSE 事件协议（step_started/step_completed/run_completed/run_failed/run_cancelled 等），未校验的结论不落最终结果展示。

## 正式 spec

- `docs/specs/ui.md` — 布局、表单、图表联动、移动端、异常状态（交互的唯一权威）
- `docs/specs/api-storage.md` — 请求响应契约与 SSE 事件协议

## 常用校验命令

- `pnpm typecheck` — 全仓类型检查
- `pnpm build` — 含 web 产物构建（验证 vite 编译通过）
