# v0.17.6 release record — 修复 api() 无 body 仍发 content-type（掐断/logout/取消 run/webhook 测试 400）

## 背景（2026-10-25 08:07 用户报障）

用户报「管理端的禁用、掐断报 502」。排查结论分两层：

1. **502 本身是发版窗口瞬时故障，非代码 bug**。Caddy 日志实锤：两条 502（PUT `chat-policy` 08:07:04 / POST `chat-cutoff` 08:07:12）均为 `dial tcp 127.0.0.1:3201: connect: connection refused`——v0.17.5 发版正在新旧容器切换（新 admin-api 08:07:17 才起来），用户的两次点击恰好落在十几秒空窗内。禁用（PUT 带 body）在新容器起来后即正常。
2. **顺着 502 挖出潜伏真 bug**：掐断按钮即使不撞发版窗口也从来没能工作过。

## Scope（PR #60，90fdcf0）

根因：`packages/shared-ui/src/api.ts` 的 `api()` 对所有请求**无条件**携带 `content-type: application/json`；POST/PUT 无 body 时浏览器仍发出该头，Fastify 对「空 body + json 头」直接抛 `FST_ERR_CTP_EMPTY_JSON_BODY`(400)，请求根本进不了 handler（解析层先于一切钩子）。

四个受害者（v0.17.5 线上 3200/3201 双进程实测全 400）：

| 调用点 | 位置 | 用户感知 |
| --- | --- | --- |
| 管理端掐断 `POST /api/admin/users/:u/chat-cutoff` | shared-ui api.ts:57 | 点确认直接报错（87bd63d 引入至今，本次首次被真正点到） |
| 退出登录 `POST /api/auth/logout` | shared-ui auth/AuthContext.tsx:40 | 前端吞错本地状态照清——**服务端会话从未真正销毁**，靠过期兜底 |
| 取消研究 run `POST /api/research/runs/:id/cancel` | web useResearchRun.ts:245 | 错误顶到 SSE 错误位，run 继续跑 |
| webhook 测试 `POST /api/settings/test` | web AlertsPage.tsx:103 | 测试按钮报错 |

修复（单点）：仅当 `body !== undefined` 时携带 content-type 头；无头无体的 POST/PUT Fastify 直接跳过 body 解析。GET 不再带无意义的 json 头。
