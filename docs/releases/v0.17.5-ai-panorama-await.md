# v0.17.5 release record — 修复 AI 全景 conversations 漏 await（be.some 崩溃）

## Scope（PR #58，05c8c6f）

2026-10-24 晚线上实锤：管理端 AI 页 → 旧会话 → 点用户名打开「用户全景」抽屉即崩，整页被路由错误边界替换为 `be.some is not a function`（admin-api 日志时间线：`/ai/overview → 200` 后 2 秒 `/ai/user?username=zhouchangkun → 200`，随后无任何后续请求=前端崩溃）。

根因与修复：

- `server/src/admin/routes.ts` `/api/admin/ai/user`：`listAiConversations(username)` 是 async（内部 `ensureFresh`），漏 `await` 把 **Promise 对象**序列化成 `{}` 发给前端；antd Table 嵌套行检测（压缩后 `be.some(...)`）对非数组调用 `.some` 抛 TypeError。补 `await`（附约束注释）。
- 同款：`server/src/index.ts` `/api/ai/conversations` 同函数同样漏 `await`，一并修复（该端点前端已不走，属潜伏修复）。
- 回归钉住：`scripts/admin-dual-entry-check.ts` 新增 D22/D23——两侧响应的 `conversations` 字段必须 `Array.isArray` 为真（21 → 23 项）。该行代码自 87bd63d（v0.7 收口）即如此，旧界面未触达，新 UI 错误边界使其显性化。

线上证据链（诊断实录）：容器内以 dist 同款代码实测 `listConversations('zhouchangkun')` 返回非数组（Promise）；前端产物 `views-*.js` 全量扫描 `be.some(` 唯一命中=antd Table 嵌套行检测；抽屉内 memories/conversations 两表 dataSource 无 `?? []` 兜底（memories 服务端有 await 故正常）。
