会员集成使用每次新建的独立数据库和临时资料目录，不调用真实模型。覆盖不可变版本、提前/过期续费、切换保留用量、月末与闰年、终身、试用重复拒绝、旧账号显式迁移、功能权限、分钟窗口及北京时间跨日计数。预置 99 位优惠用户后并发竞争最后一个名额，验证只有第 100 位成功、第 101 位完整回滚。

HTTP 检查包含失败退额、202 成功受理计次、重复幂等键重放、流式聊天 hijack 路径结算与失败退额、崩溃预占回收、会员停用及到期后的下一请求拦截。AI 检查覆盖聊天/研究独立档案、研究快照冻结及密钥不写入快照。本人状态不返回管理员标识、后台刷新配置或 AI 连接信息。

轮询检查覆盖同资源多订阅共享请求、慢请求不重叠、定时/聚焦/操作合并、隐藏和离线暂停、恢复补查、8 秒超时、旧账号响应隔离、到期/日界补查、30/300 秒间隔、动态配置、抖动调度、失败保留数据、指数退避及 Retry-After。后台保存时使当前相关数据失效，避免列表与汇总继续显示旧状态。

## 本地容量基线与未完成的部署验收

原始报告：[membership-load-local.json](membership-load-local.json)。命令为 `pnpm membership:load`，默认 1,000 个逻辑可见页面、60 秒间隔加 0–10% 抖动、15 分钟，真实 HTTP 与独立 PostgreSQL 数据库。中途更新全局刷新配置版本，另测 1,000 次同时进入。

| 指标 | 稳定刷新 | 集中进入 |
|---|---:|---:|
| 请求数 | 14,311 | 1,001（含 1 次预热） |
| p95 | 5.10ms | 324.17ms |
| p99 | 8.02ms | 334.00ms |
| 错误数 | 0 | 0 |

共 15,312 次请求，持续 900.003 秒。测量包含压测客户端的有界连接池排队时间（最多 50 条 HTTP 连接）；不包含真实登录认证、反向代理及生产网络。数据库与其他本地容器共享资源，不能证明与目标部署同等资源，也没有取得生产连接池等待指标。

稳定刷新达到所设延迟目标；集中进入的端到端 p95 高于 300ms 目标。不能据此将生产容量验收标记为通过。上线前应在目标资源下，以真实认证与代理链路执行同等压测，记录连接池队列、数据库查询与 HTTP 延迟，并验证所有阶段的 p95 ≤300ms、p99 ≤1s、错误率 <0.1%。

压测初版客户端曾一次建立 1,000 条本机连接，触发 TCP 连接重置；该结果未计作通过。改为有界连接池后完成以上 15 分钟实测，保留集中进入的排队耗时。

## 上线顺序

1. 部署 `0035_membership` 与数据库权限白名单，再启动兼容的 API 和 worker。
2. 管理员确认 AI 档案、价格和额度后发布套餐；初始四个套餐均为草稿，优惠活动默认关闭。
3. 人工确认收款、开通或续费；逐个显式迁移旧账号。
4. 观察会员状态查询指标，并完成上述目标部署容量验收。

管理员操作步骤另同步到本地 `docs/admin-manual-v3.md`；该文件按仓库原有规则不入库。

本地另构建 `biance-vision-membership-check` 与 `biance-vision-membership-website-check` 镜像。应用构建补齐既有 workspace 契约包的 manifest 拷贝；官网先构建共享轮询模块。镜像构建不代表已部署或迁移线上数据。
