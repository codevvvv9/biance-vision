# 知识库 RAG 完全指南：从上传 Brooks PDF 到被 AI 引用

> 面向对象：超级管理员。目标读者是「接下来要大量上传 Brooks PDF 讲解资料」的运营者。
> 本手册把知识库的**完整链路**一步一步讲清楚：每一步系统在做什么、你怎么确认它做对了、做错了去哪看。
> 配套：后台页面操作见本地《管理后台操作手册》（手册文档不入库，保存在本地）。

---

## 〇、一分钟看懂全链路

```
上传(PDF) ──► 解析(Docling→块) ──► 切分(结构感知 chunk) ──► 向量化(pgvector)
                                                                    │
   研究提问 ──► 检索(词项+向量+规则卡+案例 → RRF 融合 → 精排) ◄── 发布(知识版本)
                                                                    │
                        证据引用(精确到页码/图号) ◄──────────────────┘
```

七个关键事实（后面每条都会展开）：

1. **只有「发布」之后，资料才会被 AI 检索到**——上传/解析完成不等于可用。
2. **PDF/DOCX 解析靠 research-py 容器里的 Docling**（v0.9.2 起发版镜像自带；此前版本的镜像不带，上传 PDF 会显示 failed）；TXT/MD/HTML 走 Node 原生解析，不依赖它。
3. **检索是三层召回 + 融合 + 精排**：词项（关键词）+ 向量（语义）+ 规则卡/案例（增强层）→ RRF 融合 → rerank 精排。任何一层缺席系统都会显式说明，不会静默降级。
4. **每次发布产生一个「知识版本」**；每条研究运行冻结它启动时的知识版本——这是复现性的来源（同一个 run 重放，引用的资料一模一样）。
5. **证据引用精确到页码/图号**——这是切分层保留 PDF 页码信息的结果，也是你验收解析质量的重点。
6. **规则卡是给核心概念加的「权威摘要层」**：一概念一卡，发布后作为独立召回层参与检索，AI 优先拿到最凝练的定义。
7. **检索调试面板是你的听诊器**：任何「AI 怎么没引用到某段资料」的问题，先去那里看流水线每一阶段的命中数。

## 一、开工前：三个开关检查（只做一次）

### 1.1 Docling（PDF 解析层）

进「管理后台 → Agent 配置」……不，这一项没有页面开关，**看状态的方式**：上传一个 PDF，如果解析状态一直显示 failed 且原因含「docling」，说明当前镜像不带解析层（v0.9.2 之前的版本）。升级到 v0.9.2+ 即解决。TXT/MD 不受影响。

### 1.2 embedding 能力（向量召回层）

进「Agent 配置 → 能力配置」，看 **embedding** 是否已启用并配置了可用的 OpenAI 兼容接口。没配置的后果：检索只剩词项匹配（同义词/换说法搜不到），AI 引用质量明显下降。**大量上传 PDF 前强烈建议配好。**

### 1.3 rerank 能力（精排层）

同一页看 **rerank** 是否启用。没配置：融合结果直接输出，排序略糙但可用。

> 三项就绪的完整状态，可以在「知识库 → 检索调试」里输入任意问题验证：流水线条上「向量」「精排」两个数字**不为 —** 即活着。

---

## 二、第一步：上传

入口：**管理后台 → 知识库** 页顶部的导入区，三种通道：

| 通道 | 怎么用 | 适合 |
| --- | --- | --- |
| **文件上传** | 拖拽或点击选择文件，可多选；每个文件一条独立状态进度 | 日常：单个/几个 PDF |
| **URL 导入** | 粘贴网页地址（HTML/在线 PDF） | 公开的网页文章 |
| **manifest 批量导入** | 粘贴/上传清单（文件名+标题+来源层级列表），系统核对哪些已导入哪些待上传 | **整本书/成批几十个文件的场景**（推荐先建 manifest 再逐个传） |

**硬约束**：支持 `.pdf / .docx / .txt / .md / .html`，单文件 ≤ 50MB。

**来源层级（sourceTier）**：上传时可选 `official`（Brooks 官方出版物）/ `community`（社区讲解）/ `ai_generated` 等。**商业出版物的 PDF 请确认你有合法的使用权限**——这个字段会跟随证据展示，是内容合规的声明。

上传后每个文件在知识库列表里得到一条记录，初始状态为**待处理**。

---

## 三、第二步：解析——系统把 PDF 变成「块」

点击文档（或批量处理）后，系统把文件送入解析层：

1. **PDF/DOCX → research-py 的 Docling**：识别出文本、标题（含层级）、表格、图示（figure），**并保留每块内容所在的页码**；图示会得到图号。
2. **TXT/MD/HTML → Node 原生解析**：MD 按井号标题分层，HTML 按标签，同样输出统一块结构。

**验收点**：解析完成后点开文档「预览」，你应当看到——

- 标题结构正确（章节层级没有串）；
- 正文段落完整（PDF 双栏排版常见的问题是栏序错乱，扫一眼即可发现）；
- **页码存在**（预览里块上标着页码；后面 AI 引用时「《xxx》第 87 页」就靠它）；
- 表格/图示被识别为独立块（不是糊成一团文字）。

**扫描版 PDF（纯图片无文字层）解析不出来**——需要先 OCR。Docling 对图片型 PDF 的支持有限，遇到正文为空的解析结果基本就是扫描件。

---

## 四、第三步：切分与向量化——为检索做准备

解析完成后系统自动执行（无需手动触发）：

1. **结构感知切分**：按标题路径把内容切成 chunk（每块带完整标题路径，如 `["第三章 反转", "楔形"]`），句界优先、相邻块保留尾句重叠——保证一个概念跨页/跨段时不被切断丢上下文。**页码与图号跟随 chunk 保留**。
2. **向量化**：每个 chunk 调 embedding 接口转成向量存入 pgvector。这一步消耗 embedding 接口调用量（一个大 PDF 数百 chunk = 数百次 embed），**批量上传时按本本节奏传**，不用一次几十个文件挤进去。

状态机会依次推进：`待处理 → 已解析 → 已切分 → 已向量化`。任何一步失败，状态条会显示原因。

> 上传但还没发布的资料**不会**被研究检索到——这是设计（防止半成品资料污染结论），也意味着你可以从容地传完、预览完、确认质量后再统一发布。

---

## 五、第四步：发布——让资料进入检索，并形成「知识版本」

点文档卡上的「发布」（可多选后批量发布）：

1. 该文档的全部 chunk 正式进入检索范围；
2. 系统生成一个新的**知识版本号**（knowledge version）；
3. 此后每次研究运行启动时**冻结当时的知识版本**——今天发起的研究永远引用今天已发布的资料；明天你上传了新书，昨天的研究重放时引用不变。这就是「结论可复现」的机制来源。

**推荐节奏（重要）**：整本书传完、预览校对完、配套规则卡写完后**一次性发布**，形成一个干净的知识版本；避免一节一节发（每发一次就多一个版本号，虽无害但版本历史会碎）。

---

## 六、第五步：检索验证——用「检索调试」当听诊器

入口：知识库页右侧「检索调试」面板。输入一个真实研究问题（例如 `楔形三推反转的成立条件是什么`），回车，流水线显示五个阶段的命中数：

| 阶段 | 含义 | 数字为 0 时查什么 |
| --- | --- | --- |
| **变体** | LLM 对问题的改写（如「wedge 三推」中英互换、同义扩展） | chat 能力未配置则无变体，只有原查询 |
| **词项** | 关键词在 chunk 词项数组上的交集命中 | 关键词拼写/术语是否入库（试英文原词 wedge） |
| **向量** | pgvector 语义近邻命中 | embedding 能力是否配置；文档是否已向量化 |
| **融合** | 词项+向量+规则卡+案例四路 RRF 融合后的候选 | 前面全 0 则融合也是 0 |
| **精排** | rerank 对融合候选重排 | rerank 未配置则跳过（显示提示） |

命中卡片可展开看 chunk 原文、所属文档、**页码**、标题路径——这就是将来 AI 引用时展示的内容。

**验收一批新资料的标准动作**：为这本书挑 5~10 个核心术语（wedge、second entry、barb wire、climax、measured move…），逐个在检索调试里查，确认命中的是你新传的书且页码正确。

---

## 七、第六步：被研究引用——用户侧看到什么

资料发布后，无需任何配置，两条链路自动用上：

1. **概念问答**（`什么是楔形`）：AI 从知识库检索支持片段 + 反证片段作答，回复中的 `[1] [2]` 编号对应证据，点开可看**文档名 + 页码 + 原文**；
2. **结构研究**（run）：检索阶段作为研究的一环（运行气泡的「知识检索」步骤），结果卡的论断与综合解释引用这些证据，同样精确到页码/图号。

**常见疑问：AI 为什么引用了另一本书而不是新传的？**——检索按相关度排序，不是按新旧。如果希望某个概念优先引用特定资料，用下一节的规则卡。

---

## 八、进阶：规则卡与案例窗（给核心概念加权威层）

### 8.1 规则卡：一概念一卡

把最重要的概念（建议先做 20~30 个 Brooks 核心概念）写成结构化卡片：概念名、定义、成立条件、失效条件、易混淆点、原文出处。入口：知识库页「规则卡」面板 → 新建草稿 → 发布。

发布后规则卡作为**独立召回层**参与每次检索：问「什么是铁丝网」时，AI 同时拿到规则卡的权威摘要和原文 chunk——回答更凝练，且卡片可精确定制你想强调的口径。

### 8.2 案例窗：历史行情案例

把「某年某月 BTC 的某段走势属于什么结构」整理成案例（配图说明、注释、结论），发布后进入检索——AI 讲解概念时可以引用真实历史案例佐证。

> 规则卡与案例同样遵循**发布后可见 + as-of 版本过滤**纪律。

## 九、Brooks PDF 批量导入最佳实践（汇总）

1. **先建 manifest**：整本书开传前，列一份文件清单（文件名/标题/来源层级），导入区「manifest」通道一次核对，避免重传漏传。
2. **按章拆分优于整本一个 PDF**：几百页的大 PDF 可以上传，但按章拆分后——标题路径更干净、解析失败重传代价小、预览校对方便。Brooks 三部曲建议按章拆。
3. **来源层级如实填**：官方出版物选 official；社区讲解选 community；AI 生成的笔记选 ai_generated（证据展示会带来源层级）。
4. **扫描件先 OCR**：无文字层的 PDF 解析不出内容。
5. **每本配规则卡**：书传完后，把该书最核心的概念（每章 3~5 个）沉淀成规则卡——这是让问答质量从「能搜到」提升到「答得准」的最大杠杆。
6. **发布前用检索调试验收**：核心术语逐个查一遍（第六节的标准动作），页码对、命中对再发布。
7. **整本节奏发布**：一章一章传，一本书一批发布，形成清晰的知识版本线。
8. **向量化有成本**：embedding 按 chunk 计费（一个 PDF 数百 chunk），大批量上传避开使用高峰、分批进行。

## 十、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| PDF 上传后解析 failed，原因含 docling | 镜像不带解析层（v0.9.2 前） | 升级到 v0.9.2+（联系开发人员） |
| 解析成功但正文为空 | 扫描版 PDF 无文字层 | 先 OCR 再上传 |
| 检索调试「向量」为 0/— | embedding 能力未配置或文档未向量化 | Agent 配置里启用 embedding；等向量化状态完成 |
| 检索调试「精排」为 0/— | rerank 能力未配置 | 可选；启用后排序更准 |
| 明明上传了却搜不到 | 文档未「发布」 | 发布后重试 |
| 搜中文术语搜不到，英文能搜到（或反之） | 词项层精确匹配 + 向量层语义匹配的差异 | 用检索调试看「变体」是否生成了中英互换；核心概念建规则卡兜底 |
| AI 引用的页码和 PDF 对不上 | 解析层页码识别错误（罕见，多见于排版复杂的 PDF） | 预览里核对该页；确有问题则该版本解析质量差，考虑按章拆分重传 |
| 引用了一本旧资料而非新书 | 检索按相关度不按新旧 | 为该概念建/更新规则卡；或旧资料内容确实更相关 |
