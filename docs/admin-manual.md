# Biance Vision 管理后台操作手册（超管版）

> 面向对象：超级管理员（超管）。管理后台所有页面与接口仅超管可见可用，普通用户访问会被拒绝。
> 本手册只讲页面操作；涉及服务器、命令行、数据库的事项一律联系开发人员处理。
> 配套文档：最终用户视角见 [user-manual.md](user-manual.md)。

## 一、先读这里（3 分钟上手）

### 1.1 超管账号从哪来

系统不开放自助注册（注册页只显示「暂未开放注册」）。**超管账号由部署系统的开发人员创建并交付给你**；需要新增账号、找回或重置密码时，同样联系开发人员。

### 1.2 怎么进管理后台

1. 用超管账号登录。
2. 点页面右上角的「用户名 超管」按钮，展开下拉菜单。
3. 下拉菜单里**直接平铺列出五个后台页面**（没有单独的「管理后台」入口项），点哪一个就进哪一页：

| 菜单项（副标题） | 这页管什么 |
| --- | --- |
| 管理面板（用户 / 日志） | 用户列表、禁用与每日限量、操作日志 |
| AI 会话（上下文 / 记忆） | 研究会话追踪、生效配置、长期记忆、系统提示词 |
| 知识库（导入 / 发布 / 检索调试） | 资料导入、解析发布、检索调试、规则卡、案例窗 |
| Agent 配置（能力 / 版本 / 回滚） | 研究流水线的五类模型能力、版本发布与回滚 |
| 评测与模型（数据集 / 训练 / 指标） | 评测数据集、评测运行、概率模型训练 |

进入后台后，顶部有同样的五个页面导航，左上角「← 返回主站」可回到行情页面。

### 1.3 两套 AI 配置，别搞混（最重要的一节）

系统里有两个地方都能"配模型"，管的完全是两件事。配错地方是最常见的新手错误：

| | 「AI 设置」弹窗 | 「Agent 配置」页 |
| --- | --- | --- |
| 从哪进 | 用户菜单 →「AI 设置」 | 用户菜单 →「Agent 配置」 |
| 管什么 | 用户侧的 **AI 助手聊天**（右下角机器人对话） | **研究终端**的研究流水线 + 知识库的向量化/精排/图示理解/网页搜索 |
| 按谁生效 | 按「配置档案」绑定到具体用户，未绑定的走 `default` | 全站统一，取"当前发布的 Agent 版本"或全局设置 |
| 密钥怎么填 | 直接粘贴 API Key（只存服务端，界面回显打码） | 只填「密钥引用名」，引用名找开发人员要 |
| 详见 | 第四节 | 第七节 |

一句话：**用户聊天不工作 → 查「AI 设置」；研究跑不动 / 知识库检索不行 → 查「Agent 配置」。**

## 二、常见任务速查

| 我要…… | 去哪 | 看哪节 |

## 三、管理面板：用户与聊天管控

这页管"人"：谁能用 AI、每天能用几次、谁在什么时候做了什么。页面不自动刷新，用户列表和操作日志右上角各有「刷新」按钮，点一下取最新数据。

### 3.1 用户列表

展示所有用户：用户名、角色（超级管理员/普通用户）、聊天状态、创建时间。

「聊天」列同时展示三件事：

- **禁用状态**：`正常` / `已禁用`（禁用只影响 AI 聊天与研究，不影响登录看行情）。
- **今日用量**：`已用/上限`（如 `12/50`；上限显示「不限」表示未设置）。
- **在线状态**：5 分钟内有操作显示「在线」，否则显示「离线」。

### 3.2 每行的管控操作

| 操作 | 用法 | 效果 |
| --- | --- | --- |
| 复制 | 点击复制用户名（成功后短暂显示「✓ 已复制」） | 「AI 设置」里绑定用户需精确匹配用户名（区分大小写），直接粘贴避免手误 |
| 禁用 / 启用 | 切换按钮 | 禁用后该用户无法使用 AI 聊天与发起研究；可随时恢复 |
| 每日上限 | 输入正整数后回车或点「设」 | 限制该用户每天可发送的聊天消息数；**留空提交 = 不限**；非正整数会被拒绝并提示 |
| 掐断 | 点击后需二次确认 | 一键禁用该用户聊天 **并取消其全部进行中的研究任务**（防滥用场景用）；执行完会弹窗告知禁用结果和取消了几个任务；若数据库暂不可用，取消会被延迟，可在 AI 会话页复查 |

执行任一操作时其他行的按钮会短暂禁用（全局互斥），避免并发写冲突。

> 「每日上限」与「AI 设置」里档案的「每人每日次数」是两层独立限量，同时生效、取严。详见第九节。

### 3.3 操作日志

- 一次登录 = 一条会话记录；来源 IP 显示在行内，设备信息**悬停行**查看，点行展开可看该次登录后的完整操作路径。
- 登录失败单独记录并以红色标注。
- 可按用户名筛选；系统保留最近 200 条会话记录。

## 四、AI 设置弹窗：给用户配聊天模型

这节讲"AI 助手聊天"的模型配置——用户右下角机器人能不能用、用什么模型，全在这里。

**入口**：点右上角「用户名 超管」→ 下拉菜单 →「AI 设置」（菜单项右侧会显示当前模型名或「未配置」），弹出「AI 大模型设置」窗口。

### 4.1 先懂「配置档案」

**档案 = 一整套模型配置**（Base URL + API Key + 模型 + 参数）。可以建多个档案：

- `default` 档案：**总开关**。只有 default 档案填完整（Base URL、API Key、模型三者齐全），全站用户才能看到并使用 AI 助手入口；它同时是所有未绑定用户的兜底配置。`default` 不可删除。
- 自建档案：点「＋ 新建」输入档案名（1~24 位字母/数字/`_`/`-`），用来给特定用户单独配模型或限量。**只建自建档案而 default 没配完整，全站 AI 助手入口不会出现。**
- 删除自建档案后，绑定它的用户自动回落到 `default`。

### 4.2 字段逐项说明

| 字段 | 说明 |
| --- | --- |
| Base URL | OpenAI 兼容接口地址，默认 `https://api.openai.com/v1`（DeepSeek / Moonshot / 中转等兼容接口都填这里） |
| API Key | 密钥，密码框输入；只存服务端，界面回显打码，不下发浏览器 |
| 模型名称 | 如 `gpt-4o-mini`；接口支持时会拉取模型列表，可下拉选择 |
| temperature | 0~2，留空 = 0.7 |
| 输出上限 | 单次回复长度上限，留空 = 不限 |
| 每人每日次数 | 使用本档案的**每个用户**每天可对话次数，留空 = 不限（档案级限量，见第九节） |
| 工具调用 | 默认开启：AI 可调用行情查询 / 技术分析 / 画图等工具；模型不支持时自动降级为纯对话 |
| 绑定用户 | 仅自建档案显示。逗号分隔，或直接点下方用户标签点选；绑定按用户名精确匹配（区分大小写），输错名字会出现黄字提醒。绑定的用户使用本档案而非 default |
| 追加系统提示词 | 追加在内置金融分析提示词之后（如"回答控制在 300 字内"）；点「❗ 查看当前生效提示词」可看完整下发的提示词 |

### 4.3 标准操作流程

1. 用户菜单 →「AI 设置」，确认当前选中 `default`（或「＋ 新建」一个档案）。
2. 填 Base URL、API Key、模型名称。
3. 点「测试连接」，显示「连接成功，Key 有效」再继续。
4. （可选）设「每人每日次数」、绑定用户、追加提示词。
5. 点「保存」。**保存即生效，无需重启服务**。

「清空全部」按钮（仅在已配置时出现，需确认）会删除所有档案，删除后机器人与聊天窗口不再出现，可随时重新配置。

## 五、AI 会话：排查用户侧 AI 行为

这页管"审计与排查"：用户反馈 AI 异常时来这里找证据。页面不会自动刷新，重新进入或切换选择即可看到最新数据。

页面分两块使用（两块各有「刷新」按钮，页面不自动刷新）：

1. **研究会话**：先在面板顶部「选择用户」下拉里选一个用户，下方才会列出该用户的研究会话，可展开查看完整消息（含内嵌的研究结果卡摘要与系统消息；带意图标签、持仓确认卡、关联研究运行标记）。
2. **AI 助手（旧链路）**：旧版聊天链路的会话记录（前端已切换到研究会话链路，仅作追溯）。**在这张表里点选某个用户行**，下方才会出现该用户的四个详情面板：
   - **生效配置**：该用户当前生效的 AI 配置档案（模型、API Key 打码、temperature、输出上限、每日限额、追加提示词、绑定用户名）。
   - **长期记忆**：系统为该用户沉淀的长期记忆条目（偏好/事实/兴趣等，带类型标签）。
   - **会话上下文**：该用户旧链路的会话列表（标题/消息数/时间），可展开逐条消息。
   - **生效系统提示词**：当前实际下发给模型的系统提示词全文，默认折叠，点「查看」展开（只读）。

排查思路：用户反馈「AI 回答不对/不记得我」时，先看生效配置与生效系统提示词确认档案正确，再看研究会话定位具体轮次，必要时查长期记忆是否污染。

## 六、知识库管理

这页管"资料"：AI 回答时引用的知识全来自这里。整体流水线：**导入 → 解析 → 切分 → 索引 → 发布 → 检索可见**。资料只有「发布」之后才会被研究/聊天的检索命中。

### 6.1 三种导入通道

| 通道 | 操作 | 说明 |
| --- | --- | --- |
| 文件上传 | 拖拽文件到上传区，或点击选择（可多选） | 上传对话框默认筛选 `.pdf` `.docx` `.txt` `.md` `.html`，单文件 ≤50MB（超限文件自动跳过并提示）；逐文件显示上传状态；重复内容会提示「重复，未新建」 |
| URL 导入 | 输入 URL 点「导入」 | 抓取公开网页入队解析；遇访问限制会如实失败，不做绕过 |
| 清单批量导入 | 点「从默认清单导入」 | 清单内容由开发人员预先维护，你只管用按钮导入；返回「新 / 重复 / 失败 / 待上传」统计 |

**使用权纪律（务必遵守）**：商业书籍、会员资料**只能通过「文件上传」导入你拥有使用权的文件**。每张资料卡片和预览抽屉都带来源标记（来源等级：官方 / 官方衍生 / 社区；使用权：购买 / 会员），自查资料来历时可对照。

### 6.2 文档状态机与发布

文档卡片按状态流转（卡片左侧色条 + 状态徽章）：

```
待解析 → 解析中(闪烁) → 已解析 → 已切分 → 待发布(琥珀色) → 已发布(绿色)
                       ↘ 失败(红色，悬停显示失败原因)
```

- **解析中**页面每 3 秒自动刷新，完成后自动停在最新状态。
- 顶部统计条：资料 / 已发布 / 待发布 / 解析中 / 失败；下方筛选胶囊可按「全部 / 已发布 / 待发布 / 解析中 / 失败」过滤卡片。
- **发布**：只有「待发布」状态的卡片能点「发布」，发布后进入当前知识版本，检索即可命中。
- **重解析**：解析失败或想重新处理时点「重解析」（解析进行中不显示该按钮）。
- 同一文件重复上传不会产生重复文档（按内容去重）。

### 6.3 预览（点击任意文档卡片或卡上「预览」）

右侧滑出预览抽屉，两个页签：

- **分块**：解析切分后的切块列表，Markdown 渲染（表格/代码块/加粗等）；被截断的块可点「展开全文」拉取完整文本；顶部可展开查看解析元数据与向量索引状态。
- **原文**：PDF/网页用浏览器原生渲染内嵌预览；Markdown 按原文展示；TXT 纯文本；DOCX 提供下载（浏览器不支持原生预览）；URL/清单导入的资料没有本地文件，会如实提示。

抽屉内可直接执行「重解析 / 发布上线」；按 Esc 或点遮罩关闭。

### 6.4 检索调试

验证「某个问题能不能检索到、检索质量如何」：

1. 输入测试查询（如 `H2 是什么`）。
2. 选择方向：「支持依据」或「反例」（反证检索）。
3. 点「查询」，查看：
   - **流水线打点**：变体 → 词项 → 向量 → 融合 → 精排 → 命中，各阶段数量（悬停看说明；精排为 0 表示未配置精排能力，流水线自动跳过）。
   - **命中卡片**：来源文档、页码、图号、类型（正文/图示/表格）、来源等级，正文 Markdown 渲染。
4. 短词（H2/L2/ii/ioi 等）依赖词项召回与同义词表，不靠向量相似度——命中异常时先看词项阶段数量。

### 6.5 规则卡（一概念一卡）

概念知识卡片的「AI 草拟 → 人工审核 → 发布」流程：

1. 输入概念（如 `h2` / `barbwire` / `mtr`），点「草拟（LLM/模板）」生成草稿。
2. 草稿卡（虚线边框）点「编辑」，补全/修正定义、成立条件、失效条件（界面提示用「；」分隔，半角 `;` 同样接受）。
3. 「保存草稿」后点「发布」上线；也可「删除」。
4. 纪律：规则卡由人工审核后发布；资料正文更新不会自动改动规则内容。

### 6.6 案例窗

为「结构识别案例」建立训练/检索样本：

1. 输入交易对（如 `BTCUSDT`）、K 线周期（下拉可选 5m / 15m / 1h / 4h，市场固定为 USDT 永续）、人工结构标注（如「多头回调 H2 二次进场」）。
2. 点「构建案例窗」生成待审核案例。
3. 在列表里核对案例（状态「待审核」，可查看决策时的结构 regime 等字段）后点「发布」，状态变为「已发布」。
4. 说明：决策可见内容与未来结果**分开存储**（防泄漏），检索只返回可见字段。

### 6.7 资料清单（批量导入源）

「从默认清单导入」背后的清单是项目里的 `docs/references/knowledge-source-manifest.json`（一份资料条目列表），由开发人员维护，页面导入卡片上也会标注这个路径。开发人员更新清单后，你在页面点「从默认清单导入」即可增量导入，无需其他操作。

## 七、Agent 配置：研究流水线的模型与版本

这页管"研究终端"背后的模型能力（与第四节的用户聊天配置是两套，见 1.3）。分两大块：**能力配置**（当前生效）与**版本流**（可回滚的配置历史）。

### 7.1 能力配置

五类能力，每类一张卡（开关 + 状态灯）：

| 能力 | 用途 | 关键参数 |
| --- | --- | --- |
| 对话生成 chat | 研究流水线使用的大模型 | 接口地址、模型名 |
| 向量化 embedding | 把知识切块转成向量，供检索 | 接口地址、模型名、**维度（默认 1536，改动前必须先联系开发人员，需同步重建索引）** |
| 精排 rerank | 检索结果精排 | 未启用时检索流水线自动跳过精排 |
| 图示理解 vision | 书中图示理解（多模态模型） | 接口地址、模型名 |
| 网页搜索 search | 反证/新闻检索与原页抓取 | 白名单域名（逗号分隔，留空不限制）、超时、体积上限、结果数 |

状态灯：绿 = 已启用且模型已填；琥珀 = 已启用但模型未填；灰 = 停用。

通用操作：

1. 打开能力开关。
2. 填写接口地址 / 模型名 / 密钥引用名。**密钥本体由开发人员在服务端保管，这里只填引用名（引用名找开发人员要）**，界面上不出现任何密钥明文。
3. 点「保存能力配置」持久化。
4. 点「测试连通性（按表单值）」可**在保存前**验证表单当前值是否可用，结果以表格展示（能力/状态/说明/耗时；向量化会报告实际维度）——**建议改完先测再存**。

配置来源说明：能力配置优先取「当前发布的 Agent 版本」，否则回落到全局设置；页面会标注当前来源。

### 7.2 版本流（草稿 → 发布 → 回滚）

**版本 = 一份完整 Agent 配置的快照**。发布后立即生效且不可改，出问题可一键回退：

1. 输入版本标签（如 `v1.0.0`）点「新建草稿」。
2. 在下方**配置编辑区（一段 JSON 文本）**里修改后点「存当前编辑」（草稿可反复修改）。配置内容包括：五类能力（同上）、研究角色定义、检索参数、规则参数、调用预算上限。**要改哪个字段、怎么写，先找开发人员要写法**——JSON 格式写错，保存时会直接提示「配置 JSON 解析失败」。
3. 草稿点「发布」成为不可变版本并立即生效（版本列表中标「← 当前发布」）；已发布版本可「回滚到此」；任意版本可「调试运行」，结果面板展示连通性逐项检查与检索冒烟命中情况。

> 提示：检索参数（变体数、候选数、最终条数等）是**起始值**，最终以评测集调优为准（见第八节），不要把默认值当作"最佳实践"。

## 八、评测与模型

这页管"效果验证"：改完知识库/检索参数后跑评测，以及训练概率预测模型。页面顶部显示解析/训练服务的健康状态，显示「不可达」时会附带一条修复命令提示——不用自己执行，把整行提示原样发给开发人员即可；页面每 8 秒自动刷新。

### 8.1 数据集

- 类型二选一：`RAG 检索`（验证"某个问题能否检索到预期文档"）或 `结构回放`（验证行情结构识别）。
- 填名称 + 条目内容 → 点「创建」。条目是固定格式的 JSON，**输入框里自带灰字格式样例**（如 RAG 型的 `[{"query":"H2 是什么","expectDocTitle":"术语表"}]`），照着结构写即可，拿不准再找开发人员。
- 数据集版本化：**同名（同类型）再次创建会升为新版本，与内容是否相同无关**；旧版本保留。
- 当前界面不提供数据集的编辑/删除，如确需请联系开发人员。

### 8.2 评测运行

- 对数据集点「运行评测」入队，页面 8 秒自动刷新状态。
- 完成后点「报告」展开查看完整指标明细。
- 用途：验证知识库/检索参数改动的效果（配合 6.4 检索调试），以及模型是否达标。

### 8.3 模型注册表与训练

- 「触发训练」：输入模型版本名（如 `qgb-10m-001`）+ 期限（10m/30m/1h/1d/1w）。
- 状态机：`训练中 → 候选 → 已发布`；注册表展示训练截止时间与指标。
- 注意：从「候选」到「已发布」的发布动作**当前没有界面按钮**，训练达标后联系开发人员完成发布。
- 训练数据纪律：只用**已收盘**的历史 K 线，特征只看过去、标签用未来（由系统保证，无需人工干预）。

## 九、限量与禁用一页通

"个人限量"有两层，互相独立、**同时生效、任一超限即拒（取严）**；均按北京时间自然日计数，跨天自动归零。

| | 用户级「每日上限」 | 档案级「每人每日次数」 |
| --- | --- | --- |
| 在哪设 | 管理面板 → 用户行 | AI 设置 → 配置档案 |
| 管谁 | 精确到某一个用户 | 使用该档案的每一个用户 |
| 计数口径 | 只计成功完成的交互（失败不计） | 含失败尝试（防共享刷量口径） |
| 适合场景 | 单独限制某人 | 给一批用同一档案的用户统一限量 |

相关动作的区别：

- **禁用**：关掉该用户的 AI 聊天与研究权限（登录和看行情不受影响），可随时启用恢复。
- **掐断**：= 禁用 + 同时取消该用户全部进行中的研究任务，用于滥用场景。

## 十、常见问题与故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 全站用户都看不到 AI 助手入口 | `default` 档案不完整：「AI 设置」里补齐 Base URL / API Key / 模型（三者缺一不可）并「测试连接」通过后「保存」 |
| 页面提示「PostgreSQL 不可用」 | 数据库服务异常，联系开发人员恢复；恢复后页面自动可用，无需改配置 |
| 文档一直「解析中」 | 解析服务可能异常：先看「评测与模型」页顶部的服务健康状态，显示「不可达」就联系开发人员；服务正常仍卡住可点「重解析」 |
| 文档「失败」 | 卡片红边与悬停显示失败原因；修复原因（如文件损坏重新导出）后「重解析」 |
| 预览「原文」页签提示原始文件不存在 | URL/清单导入的资料没有本地文件（正常）；若文件上传的资料也如此，联系开发人员检查服务版本 |
| 检索无命中 | 先确认文档已**发布**（未发布资料检索为空，系统不编造引用）；再用检索调试看词项/向量各阶段数量 |
| 想改向量化的维度 | 不要直接改：维度与数据库索引绑定，改动前必须先联系开发人员同步重建索引 |
| 用户反馈 AI 不可用 | 管理面板查该用户聊天状态（禁用/超每日上限）；「AI 设置」确认该用户绑定档案的密钥有效；AI 会话页查会话与生效配置 |
| 用户说研究功能报模型错误 | 研究流水线用的是「Agent 配置」页的 chat 能力，不是「AI 设置」档案；去「Agent 配置」页点「测试连通性」排查 |
| 线上看不到新功能 | 系统按版本发布，联系开发人员确认是否已发版 |
