# Biance Vision 管理后台操作手册（超管版）

> 面向对象：超级管理员（superadmin）。管理后台所有页面与接口仅超级管理员可见可用，普通用户访问会被拒绝。
> 配套文档：最终用户视角见 [user-manual.md](user-manual.md)；知识库/检索的正式规格见 [specs/knowledge-rag.md](specs/knowledge-rag.md)。

## 一、进入管理后台

1. 使用超管账号登录（账号由服务端脚本创建，系统不开放自助注册）。
2. 点击右上角用户菜单（如 `admin 超管`），选择「管理后台」进入 `/admin`。
3. 后台顶部导航共五页，与各自职责：

| 菜单 | 路径 | 管什么 |
| --- | --- | --- |
| 管理面板 | `/admin` | 用户列表、聊天管控、操作日志 |
| AI 会话 | `/admin/ai` | 研究会话追踪、生效配置、长期记忆、系统提示词 |
| 知识库 | `/admin/knowledge` | 资料导入、解析发布、检索调试、规则卡、案例窗 |
| Agent 配置 | `/admin/agents` | 五类模型能力、版本流（发布/回滚）、调试运行 |
| 评测与模型 | `/admin/evals` | 评测数据集、评测运行、概率模型训练 |

## 二、管理面板：用户与聊天管控

### 2.1 用户列表

展示所有用户：用户名、角色（超级管理员/普通用户）、聊天状态、创建时间。

「聊天」列同时展示三件事：

- **禁用状态**：`正常` / `已禁用`（禁用只影响 AI 聊天与研究，不影响登录看行情）。
- **今日用量**：`已用/上限`（如 `12/50`；上限显示「不限」表示未设置）。
- **在线状态**：5 分钟内有操作显示「在线」。

### 2.2 聊天管控操作（每行操作列）

| 操作 | 用法 | 效果 |
| --- | --- | --- |
| 复制 | 点击复制用户名 | AI 配置档案「绑定用户」需精确匹配用户名（区分大小写），直接粘贴避免手误 |
| 禁用 / 启用 | 切换按钮 | 禁用后该用户无法使用 AI 聊天与发起研究；可随时恢复 |
| 每日上限 | 输入正整数后回车或点「设」 | 限制该用户每天可发送的聊天消息数；**留空提交 = 不限**；非正整数会被拒绝 |
| 掐断 | 需二次确认 | 一键禁用该用户聊天 **并取消其全部进行中的研究任务**（防滥用场景用）；若数据库暂不可用，取消会被延迟，可在 AI 会话页复查 |

管控操作全局互斥（执行中其他行的按钮短暂禁用），避免并发写。

### 2.3 操作日志

- 一次登录 = 一条会话记录；点行展开可看该次登录后的完整操作路径（含来源 IP 与设备信息）。
- 登录失败单独记录并以红色标注。
- 可按用户名筛选；保留最近 200 条会话。

## 三、AI 会话（`/admin/ai`）

用于审计与排查用户侧 AI 行为，主要面板：

- **研究会话**：选定用户的研究会话列表，可展开查看完整消息（含内嵌的研究结果卡摘要与 system 消息）。
- **生效配置**：该用户当前生效的 AI 配置档案（模型、绑定用户名等）。
- **长期记忆**：系统为该用户沉淀的长期记忆条目（偏好/事实/兴趣等，带类型标签）。
- **会话上下文**：最近会话的上下文摘要。
- **生效系统提示词**：当前实际下发给模型的系统提示词全文（只读查看）。
- **AI 助手（旧链路）**：旧 `/api/ai/chat` 链路的会话记录，前端已切换到研究会话链路，仅作追溯。

排查思路：用户反馈「AI 回答不对/不记得我」时，先看生效配置与生效系统提示词确认档案正确，再看研究会话定位具体轮次，必要时查长期记忆是否污染。

## 四、知识库管理（`/admin/knowledge`）

整体流水线：**导入 → 解析 → 切分 → 索引 → 发布 → 检索可见**。资料只有「发布」之后才会被研究/聊天的检索命中。

### 4.1 三种导入通道

| 通道 | 操作 | 说明 |
| --- | --- | --- |
| 文件上传 | 拖拽文件到上传区，或点击选择（可多选） | 支持 `.pdf` `.docx` `.txt` `.md` `.html`，单文件 ≤50MB；逐文件显示上传状态；重复内容（内容指纹相同）会提示「重复，未新建」 |
| URL 导入 | 输入 URL 点「导入」 | 抓取公开网页入队解析；遇访问限制会如实失败，不做绕过 |
| 清单批量导入 | 点「从默认清单导入」 | 条目来自 `docs/references/knowledge-source-manifest.json`，返回「新 / 重复 / 失败 / 待上传」统计 |

默认来源等级与权限：文件上传默认 `community/public`，URL 导入默认 `official/public`。

**使用权纪律（务必遵守）**：商业书籍、会员资料**只能通过「文件上传」导入你拥有使用权的文件**；清单中 `access: purchase/member` 的条目 `importMethod` 必须为 `user_upload`。

### 4.2 文档状态机与发布

文档卡片按状态流转（卡片左侧色条 + 状态徽章）：

```
uploaded(待解析) → parsing(解析中·脉冲) → parsed(已解析) → chunked(已切分) → indexed(待发布·琥珀) → published(已发布·绿)
                                        ↘ failed(失败·红，显示失败原因)
```

- **解析中**页面每 3 秒自动刷新，完成后自动停在最新状态。
- 顶部统计条：资料总数 / 已发布 / 待发布 / 解析中 / 失败；筛选胶囊可按状态过滤卡片。
- **发布**：只有 `indexed`（待发布）状态的文档能点「发布」，发布后进入当前知识版本，检索即可命中。
- **重解析**：解析失败或想重新处理时点「重解析」（解析进行中不可点）。
- 内容指纹去重：同一文件重复上传不会产生重复文档。

### 4.3 预览（点击任意文档卡片）

右侧滑出预览抽屉，两个页签：

- **分块**：解析切分后的切块列表，Markdown 渲染（表格/代码块/加粗等）；被截断的块可点「展开全文」拉取完整文本；顶部可展开查看解析元数据与向量索引状态。
- **原文**：PDF/HTML 用浏览器原生渲染内嵌预览；MD 按原文 Markdown 展示；TXT 纯文本；DOCX 提供下载（浏览器不支持原生预览）；URL/清单导入的资料没有本地文件，会如实提示。

抽屉内可直接执行「重解析 / 发布」；Esc 或点遮罩关闭。

### 4.4 检索调试

验证「某个问题能不能检索到、检索质量如何」：

1. 输入测试查询（如 `H2 是什么`）。
2. 选择方向：「支持依据」或「反例」（反证检索）。
3. 点「查询」，查看：
   - **流水线打点**：变体 → 词项 → 向量 → 融合 → 精排 → 命中，各阶段数量（悬停看说明；精排为 0 表示未配置 rerank 能力，流水线自动跳过）。
   - **命中卡片**：来源文档、页码、图号、类型（正文/图示/表格）、来源等级，正文 Markdown 渲染。
4. 短词（H2/L2/ii/ioi 等）依赖词项召回与同义词表，不靠向量相似度——命中异常时先看词项阶段数量。

### 4.5 规则卡（一概念一卡）

概念知识卡片的「LLM 草拟 → 人工审核 → 发布」流程：

1. 输入概念（如 `h2` / `barbwire` / `mtr`），点「草拟（LLM/模板）」生成草稿。
2. 草稿卡（虚线边框）点「编辑」，补全/修正定义、成立条件（`;` 分隔）、失效条件。
3. 「保存草稿」后点「发布」上线；也可「删除」。
4. 纪律：规则卡由人工审核后发布；资料正文更新不会自动改动规则内容。

### 4.6 案例窗

为「结构识别案例」建立训练/检索样本：

1. 输入交易对（如 `BTCUSDT`）、K 线周期、人工结构标注（如「多头回调 H2 二次进场」）。
2. 点「构建案例窗」生成待审核案例。
3. 审核后点「发布」。
4. 说明：决策可见内容与未来结果**分开存储**（防泄漏），检索只返回可见字段。

### 4.7 资料清单（manifest）维护

- 文件：`docs/references/knowledge-source-manifest.json`，顶层 `{version, updatedAt, entries}`。
- 每条含 `id/url/type/topics/access/sourceTier/importMethod/enabled/notes`；**JSON 不支持注释**，改完可用
  `node -e "JSON.parse(require('fs').readFileSync('docs/references/knowledge-source-manifest.json','utf8'))"` 快速校验合法性。
- 改完清单后在页面点「从默认清单导入」即可增量导入。

## 五、Agent 配置域（`/admin/agents`）

分两大块：**能力配置**（当前生效）与**版本流**（可回滚的配置历史）。

### 5.1 能力配置

五类能力，每类一张卡（开关 + 状态灯）：

| 能力 | 用途 | 关键参数 |
| --- | --- | --- |
| 对话生成 chat | 研究/聊天使用的 LLM（OpenAI 兼容接口） | baseUrl、model |
| 向量化 embedding | 知识切块向量化 | baseUrl、model、**维度（需与库中向量列一致，默认 1536，改动需重建索引）** |
| 精排 rerank | 检索精排 | 未启用时检索流水线自动跳过精排 |
| 图示理解 vision | 书中图示理解（多模态模型） | baseUrl、model |
| 网页搜索 search | 反证/新闻检索与原页抓取 | 白名单域名（逗号分隔，留空不限制）、超时、体积上限、结果数 |

通用操作：

1. 打开能力开关（状态灯：绿=启用且配置齐备，琥珀=启用但缺 model，灰=停用）。
2. 填写 `baseUrl` / `model` / `密钥引用名`。**密钥本体存放在服务端 `server/data/secrets.json`，此处只填引用名**，界面上不出现任何密钥明文。
3. 点「保存能力配置」持久化。
4. 点「测试连通性（按表单值）」可**在保存前**验证表单当前值是否可用（embedding 会报告实际维度与耗时）——建议改完先测再存。

配置来源说明：能力配置优先取「当前发布的 Agent 版本」，否则回落到全局设置；页面会标注当前来源。

### 5.2 版本流（草稿 → 发布 → 回滚）

1. 输入版本标签（如 `v1.0.0`）点「新建草稿」。
2. 在下方 JSON 编辑区修改配置后「存当前编辑」（草稿可反复修改）。配置结构：
   - `capabilities`：五类能力（同上）
   - `roles`：研究角色定义（名称、promptRef、可用工具如 `market_snapshot`/`brooks_engine`/`knowledge_retrieval`、预算）
   - `retrieval`：检索参数（变体数、候选数、最终条数、反证条数、是否精排/邻接扩展）——这些是**起始值**，最终以评测集调优为准，不要照抄为「最佳实践」
   - `budgets`：工具调用与运行时长上限
3. 草稿点「发布」成为不可变版本并立即生效；已发布版本可「回滚到此」；任意版本可「调试运行」做连通性/检索冒烟检查。

## 六、评测与模型（`/admin/evals`）

页面顶部显示 `research-py` 服务健康状态（解析/训练的 Python 侧服务，不可达时提示 `docker compose up -d research-py`）。

### 6.1 数据集

- 类型：`RAG 检索`（条目形如 `[{"query":"H2 是什么","expectDocTitle":"术语表"}]`）或 `结构回放`（条目形如 `[{"symbol":"BTCUSDT","marketType":"usdm_perp","interval":"1h"}]`）。
- 名称 + JSON 条目 → 「创建」；数据集版本化，同内容重复创建会升版本。

### 6.2 评测运行

- 对数据集点「运行评测」入队；8 秒自动刷新状态。
- 完成后「报告」可展开查看完整指标明细（JSON）。
- 用途：验证知识库/检索参数改动的效果（配合检索调试），以及模型是否达标。

### 6.3 模型注册表与训练

- 「触发训练」：输入模型版本名（如 `qgb-10m-001`）+ 期限（10m/30m/1h/1d/1w）。
- 状态机：`training → candidate → published`，评测达标后发布；注册表展示训练截止时间与指标。
- 训练数据纪律：只用库内**已收盘** 1m K 线，特征只看过去、标签用未来；时间切分 dev/calibration/test = 70/15/15。

## 七、常见问题与故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 页面提示「PostgreSQL 不可用」(503 storage_unavailable) | 数据库未起或连接断开；恢复 DB 后页面自动可用，无需改配置 |
| 文档一直「解析中」 | PDF/DOCX 走 research-py（Docling）解析，确认其健康（evals 页顶部）；服务正常仍卡住可点「重解析」 |
| 文档「失败」 | 卡片红边与悬停显示失败原因；修复原因（如文件损坏）后「重解析」 |
| 预览「原文」页签提示原始文件不存在 | URL/清单导入的资料没有本地文件（正常）；若文件上传的资料也如此，说明线上镜像未包含原文回读端点，需 rebuild 镜像 |
| 检索无命中 | 先确认文档已**发布**（未发布资料检索为空，系统不编造引用）；再用检索调试看词项/向量各阶段数量 |
| embedding 改维度后检索异常 | 向量维度必须与库中向量列一致；改维度需重建向量索引 |
| research-py 不可达 | 服务器上 `docker compose up -d research-py`；本机开发默认 `127.0.0.1:8100` |
| 用户反馈 AI 不可用 | 管理面板查该用户聊天状态（禁用/超每日上限）；AI 会话页查会话与生效配置 |
| 线上看不到新功能/新端点 | 前端与服务端都随镜像发布，需 rebuild 镜像并重启（发版流程见部署手册） |
