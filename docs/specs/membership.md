# 可配置会员机制

状态：业务实现完成（2026-10-26），生产同资源容量验收待执行；结果见 [验收记录](../validation/membership.md)。

## 业务与配置

PostgreSQL 为套餐、会员授权和用量的唯一真源。迁移 `0035_membership` 创建四个未上架草稿：14 天免费试用（每日 10 次）、月付 15/8 USDT、年付 120/60 USDT、终身 299/100 USDT（付费默认每日 100 次，6 次/分钟，无累计上限）。金额精确到 6 位小数。

套餐的名称、双语说明、有效期、价格、功能、额度、排序、公开展示及聊天/研究 AI 档案均由后台编辑。保存草稿使用 expectedRevision；发布创建不可变版本。下架不改变存量授权。初始活动关闭，管理员确认后开启。

`founders` 活动为所有付费套餐共用的首 100 位首次付费用户优惠。免费试用不占名额；活动时间可选；续费使用届时正式价。名额通过锁定活动行及数据库唯一键控制。实收与标价不同必须填写备注。撤销收款会撤销对应授权，保留原收款及纠错原因，不自动恢复名额。

开通账号、授权、收款与名额同事务提交；operationId 持久幂等。账号密码仅返回一次，不持久化明文；重复开通返回已完成提示，丢失交付信息需重置密码。

同套餐续费从最后授权结束后开始，过期从当前时间开始。新版本仅在续费时段开始后生效。立即切换/迁移版本须确认替换当前及待生效授权，无自动折算。终身不可重复续费；每账号仅一次试用。北京时间计算日额度，月/年按日历滚动，月末截到目标月最后一天。

老账号保持原有 chatPolicy、AI 档案绑定和 ai_access 记录。显式绑定时以旧累计额度计量与 chat_usage 的当日用量较大值初始化新计数；不清空历史。管理身份不授予或隐含会员身份。

## 计量与 AI

请求链：认证 → 会员数据库校验/预占 → 功能处理 → 成功受理提交或 HTTP 失败退额。会员计量串行化同一用户的数据库事务，旧额度与档案计量对会员跳过。按账号北京时间自然日计数，续费/切换不重置；每分钟窗口限制不因失败而退回，防止失败重试刷接口。

聊天、翻译、直接研究提交和会话消息均计 1 次，内部模型/工具调用不重复计次。202 研究按成功受理计次，异步失败不自动退次。Idempotency-Key 对应相同内容可重放已受理响应，不重复执行/扣次；内容冲突返回 409。失败退额以持久 reservation 状态保证幂等及跨天正确。worker 每分钟回收超过一小时仍未结算的崩溃预占，按原日期退回；已结算响应保留 30 天后分批清理。

统一客户端为计量写操作生成幂等键，也允许调用方传入原键重试；成功和失败完成后均使本人用量失效。流式聊天在关闭原始响应前显式结算，重放仍返回文本和会话编号，避免 hijack 绕过常规响应钩子。

每次新请求直接读授权、结束时间及停用状态，展示缓存不参与判权；数据库不可用拒绝调用。到期仍可登录、查看行情及已有研究；已受理研究允许完成。

用户请求通过独立 AsyncLocalStorage 上下文绑定聊天 AI，研究创建时冻结研究 AI 连接、生成参数和套餐版本。套餐仅保存档案引用，密钥运行时在服务端解析，不写入 run 或公开响应。AI 档案仍可运维更新，已发布套餐引用的档案禁止删除。研究规则、预算和校验器不随会员档位复制或放宽。后台知识处理任务使用其系统配置。

## API

共享 schema 与 DTO：`shared/src/contract/membership.ts`。

- `GET /api/admin/membership/plans`：套餐草稿、发布版本及刷新配置。
- `PUT /api/admin/membership/plans/:id`：`{config,expectedRevision}`，新建 revision=0。
- `POST /api/admin/membership/plans/:id/publish`：`{expectedRevision}`。
- `PATCH /api/admin/membership/plans/:id`：`{enabled,expectedRevision}`。
- `GET/PUT /api/admin/membership/campaigns[/:id]`：活动、时间、名额及 expectedRevision。
- `GET/PUT /api/admin/membership/refresh-settings`：三个 30–300 秒间隔，默认 60；写入携带 expectedRevision。
- `GET /api/admin/membership/users?page=1&pageSize=20&username=`：最多每页 100 个普通用户，只查当前页。
- `GET /api/admin/membership/stats`：独立汇总，非逐用户查询。
- `GET/POST/PATCH /api/admin/users/:username/membership`：详情（最近 50 条流水/授权）、授权变更、停用/恢复。
- `POST /api/admin/membership/receipts/:id/void`：`{reason}`。
- `POST /api/admin/users/provision`：会员授权输入加可选 username；新建必须 action=bind。
- `GET /api/public/membership-plans`：公开投影，不含档案、连接、凭证或用户信息。
- `GET /api/users/me/membership`：当前/待生效授权、当日用量、旧账号剩余额度、时间、刷新配置、续费联系方式。
- 原 `/api/users/me/ai-access` 保留兼容；会员通过同一服务返回额度。旧额度写接口拒绝修改会员账号。

管理写接口须 superadmin、同源 JSON 请求并受限速保护；变更写入审计。用户 API 数据库角色只读商业配置/授权，只写 usage/reservations。公开套餐接口是精确的 GET 匿名与地域豁免，不放开其他接口。

## 刷新生命周期

用户端、管理端、官网间隔独立全局配置，均为 60 秒默认、30–300 秒边界，配置不随套餐版本冻结。查询响应携带最新配置；下一周期采用新间隔。配置与联系方式缓存最多 5 秒，并合并进程内同时读取；公开套餐最多缓存 5 秒。

共享纯 TS polling store 每页面同资源仅一个请求，React 组件用 useSyncExternalStore 订阅。递归 setTimeout 在上次请求完成后调度，周期延迟抖动 0–10%；隐藏/离线暂停，恢复或重新聚焦合并补查。操作成功使数据失效。请求超时 8 秒，失败指数退避最长 300 秒，并遵守 Retry-After；保留旧值及更新时间。退出、账号切换和最后订阅销毁取消请求、定时器、监听器，旧响应代次不能写回。

个人授权与每日用量查询使用索引，不扫描历史流水。会员卡进度根据服务端时间计算，到期和每日重置边界补查。HTTP 与状态查询耗时进入现有分钟指标采集。

## 部署与检查

先部署迁移和分权，再启动 user/admin API 与 worker，最后发布前端。首发后配置可用 AI 档案 → 编辑套餐 → 发布 → 按需开启优惠活动 → 开通账号。现有账号无需批量改动。

应用回滚不能直接让已迁移会员回到不识别会员授权的旧计量路径；回滚前先关闭会员 AI 访问并安排授权兼容处理。商业流水不随应用回滚删除。

运行 `pnpm membership:check`、`pnpm membership:load`、类型检查、构建和现有访问/登录/分权回归。负载脚本仅创建独立数据库，默认 1000 个逻辑页面、60 秒间隔、900 秒；使用真实 HTTP/PG及有界的客户端连接池，人工会话解析不覆盖生产认证/代理成本，不能替代目标部署认证。
