# Agent 对话工作台改版与双模式对比

> 状态：implemented（UI 与双模式已实现；类型、构建和浏览器受控接口回归通过，真实账号/worker 全链路待验收）
> 日期：2026-10-16
> 开发分支：`codex/dev-agent-workbench`
> 起点：当前 `main`，`662512f`

## 目标与范围

借鉴用户提供的阿福未登录/已登录截图：左侧会话导航、中央对话内容、按引用打开的右侧证据区、输入框顶部的场景标签。沿用本项目品牌、深色 token、真实数据契约和研究纪律。

该分支承接工作台 UI 改版与后续逆向研究成果的适配。分阶段提交 UI、上下文、证据和后台逻辑，使每一步可独立审阅与回退。当前已有 `dev` 分支，不覆盖它。工作区中原有未提交改动保留原样，不自动提交或归入本次工作。

UI 的正式交互约束仍以 [UI spec](./specs/ui.md) 为准；本方案的 UI 交互已实现，具体约束及验收范围同步记录在 UI spec。逆向逻辑适配仍作为后续独立变更。

## 开发分支与发布模式

Git 分支解决开发隔离；URL 参数选择同一个部署产物中包含的界面。访问 `?ui=dev` 不会自动访问 Git 的 dev 分支。

发布需包含旧、新两套页面入口及共享服务。初期同域、同账号、同 API、同会话与同研究结果，以便比较交互体验。

| URL | 预期行为 |
| --- | --- |
| `/research` | 默认旧模式 |
| `/research?ui=legacy` | 显式旧模式 |
| `/research?ui=dev` | 新对话工作台 |
| `/research?ui=dev&run=:id` | 在新模式打开指定研究 |
| `/research?ui=legacy&run=:id` | 在旧模式打开同一研究 |

- 参数名采用 `ui`，与后端生产/测试环境分开。只接受 `legacy / dev`，未知值回到旧模式。
- URL 决定当前浏览器标签页的模式；不把模式写进全局 localStorage，允许两个标签页独立对照。
- 页内提供轻量模式切换入口，保留适用的 run、会话及其他 URL 参数；切换不会创建新研究或重新运行任务。
- 登录、注册、登录成功返回、历史记录深链和浏览器前进/后退都要保留模式。
- 新旧页面按需加载、样式作用域隔离；只挂载选中的页面，避免重复拉取和重复 SSE 订阅。
- 模式参数只决定界面，不改变认证、角色、权限或数据来源。

后续改进后台逻辑时，已有 API 与 SSE 保持兼容；需要比较新旧 Agent 能力时，单独增加受服务端控制、可冻结进 run 的能力版本，不能把 `ui=dev` 同时当作模型或后台环境选择器。界面对比优先读取同一条已完成研究，避免实时行情差异干扰判断。

## 页面与交互

### 左侧：会话导航

- 品牌、折叠按钮、新建对话。
- 从真实 `/api/conversations` 获取会话，按时间分组、标出当前会话；会话加载失败和空列表分别呈现。
- 账号与登录入口放底部；大盘、价格行为及管理入口保留可达性，避免新工作台重复叠加原顶栏、行情带和悬浮助手。
- 持仓与事件报价从主导航移到对应场景工具区，避免与会话历史争占左栏。

### 中央：对话主内容

- 空会话显示项目自己的欢迎文案、三个场景和可编辑示例问题；开始对话后正文成为主内容。
- 复用已有持仓确认卡、运行气泡、取消/重试、研究结果与异常状态。
- 图表按需从结构证据或“查看图表”打开；大屏优先使用可调整的右侧研究区。原完整图表工作台可由旧模式继续访问。
- 旧回答绑定各自的 run 与快照；切换场景、标的或查看图表都不改写历史结论。
- 新消息到达时仅在用户接近底部时跟随滚动；查看历史时提供回到底部入口。

### 右侧：证据与图表

- 默认收起，点击正文引用或证据按钮后打开，并定位高亮所选条目。
- 知识引用显示冻结来源、原文片段、实际存在的页码/图号与支持/反证信息；引用编号与当前回答一一对应。
- 结构证据定位到该 run 的行情快照和具体 K 线，区分发生时间与确认时间。
- 按 `runId + evidenceId` 管理所选证据，切换回答时不显示上一研究的缓存；关闭证据区保留正文滚动位置。
- 如果当前纯文本回答尚无引用 ID 契约，先呈现已有的真实结果证据入口；正文点击定位能力随契约接线，不造虚假引用编号。

### 底部：场景标签与输入区

沿用现有三个产品场景，不把它们与移动端“图表/对话/证据”视图标签混为一谈：

| 场景标签 | 现有映射 | 输入区附属工具 |
| --- | --- | --- |
| 现货 | `product=teaching, marketType=spot` | 标的、研究周期与结构学习问题 |
| USDT 永续 | `product=perp, marketType=usdm_perp` | 已确认持仓、风险预算与持仓录入 |
| 事件合约 | `product=event, marketType=usdm_perp` | 手工报价、执行价、到期时间与期限 |

- 标签紧贴输入框上缘；随场景改变提示语与相关工具，保持输入位置稳定。
- 每个场景独立保留未发送草稿。切换产品时清理不兼容的持仓/报价关联，不删除实际持仓记录，也不把它自动带入另一个产品。
- 发送与运行期间不悄悄改变正在执行任务的场景；开始其他场景可开新会话。
- 首期不展示后端尚未支持的思考模式、附件上传等可点击控件；后续能力接入真实服务后再加入。
- 继续显示必要的标的、时点与不可用原因；1w 明确为研究模式，数值全部来自后端契约。

### 未登录与移动端

- 新模式允许查看静态欢迎页、场景介绍和编辑输入；发起研究时进入现有登录流程，保留当前草稿和返回地址。没有匿名聊天接口时，不做虚假游客回答。
- 公共外壳只做会话探测与静态展示，不挂载需要登录的 MarketProvider 或加载私人会话。
- 手机将左栏变为会话抽屉；继续保留“图表/对话/证据”视图切换，产品场景标签仍在输入区，避免左右三栏挤压。
- 引用区在手机上使用全屏层/抽屉；键盘可达、焦点返回、Escape 关闭、aria 标签和 reduced-motion 都列入验收。

## 实施拆分

1. **双模式基础**：集中解析 `ui`，拆分旧/新外壳，接好登录返回和深链参数；旧模式保持默认。
2. **新工作台主体**：会话栏、欢迎态、消息流和三个场景输入区，复用并按需整理现有 hooks。
3. **证据联动**：引用选择状态、右侧证据/图表区、历史快照定位与移动端适配。
4. **真实链路验收**：登录前后、新建/恢复会话、SSE 重连、运行取消/失败、确认卡、历史 run 和双模式切换。
5. **逆向逻辑适配**：按调查结论补任务上下文、引用支持检查、综合解释及评测；作为独立变更，不使旧模式意外失效。
   - **P0 质量闭环已完成（2026-10-16）**：按 [vertical-agent-architecture.md](./vertical-agent-architecture.md) §6 落地六项——会话评测基线（`pnpm eval:conversations`）、统一可信回答组装器（replyAssembler）、反证逐条证据绑定（[k] 标记+锚定回退）、知识三层 as-of 过滤（迁移 0016）、修复耗尽受控降级（task_degraded + degraded 发布，前端徽章/横幅双模式共用）、提示词注册表与冻结（迁移 0017，五处 LLM 调用点换链，`/api/admin/prompts` 五端点）。SSE 新增事件类型向后兼容（旧客户端忽略）。P1（场景注册表/综合解释/追问动作/画像）与 P2 待后续执行。

优先复用 `useResearchConversation`、`useResearchRun`、`useResearchCandles`、`RunBubble`、`PositionConfirmCard`、`ResearchResult` 与后端共享契约。页面外壳分别组织，业务状态与接口只维护一套；证据选择等展示状态单独收敛。
